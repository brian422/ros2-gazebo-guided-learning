# Publication and privacy checklist

## Scope of the local review

The November 2026 review inspected source/documentation text, filenames, both
stored screenshots, and the frame-graph PDF (visible content, text, metadata,
links, and attachments). No personal name, private email address, phone number,
home-directory identifier, credential, or unrelated desktop content was found
in those reviewed files. Generic maintainer details are intentionally
non-personal. Technical timestamps remain as part of the evidence record.

This is a bounded file review, not a guarantee of anonymity. It does not cover
the GitHub account profile, commit identities/history, previously published
versions, external links, or files added after the review. The supplied local
folder has no `.git` directory. GitHub can retain earlier versions after files
are updated.

## Before uploading

- Keep the guided-learning acknowledgment and accurate contribution scope.
- Include only source, lessons, and selected sanitized evidence.
- Review screenshots for usernames, notifications, and unrelated windows.
- Inspect PDF/image metadata as well as visible content.
- Check for private paths, contact details, tokens, keys, and local settings.
- Keep generated output, caches, logs, and raw captures out of uploads.
- Inspect actual Git commit author/email identities and earlier versions.
- Use the intended public display name and GitHub no-reply email for future commits.
- Do not invent a tested commit hash or backdate development activity.
- Keep private essay drafts separate from the technical repository.

`.gitignore` excludes common generated/private files, but ignore rules do not
remove previously committed content. Historical results keep their original
provenance; new source revisions need their own checks.
